# 第1章 程序设计基本方法

程序设计是把问题转化为明确的计算步骤，再用编程语言将这些步骤表达出来，交给计算机执行。开始学习时，可以围绕三个问题建立整体认识。计算机能够处理哪些任务，程序怎样运行，一个实际需求怎样拆成输入、处理和输出。圆面积计算、姓名回应和斐波那契数列等小程序，将这些概念连接成具体的执行过程。

学习时要逐步做到两件事。一是面对简单需求，能够确定数据、处理规则和输出要求。二是面对短小程序，能够说明每条语句做了什么，以及变量怎样随执行过程变化。在此基础上，再理解算法、计算思维和程序执行机制之间的联系。

## 1. 计算机、程序与程序设计

### 1.1 计算机的功能性与可编程性

计算机是按照指令处理数据的设备。数据可以是数字，也可以是文字、图片、声音或文件中的记录。对数据的处理包括算术运算，还包括比较、查找、转换、存储和传输。例如，在通讯录中查找姓名、把图片保存为文件，都属于数据处理。

理解计算机时，需要同时认识功能性与可编程性。

- **功能性**体现为能够对数据进行输入、计算、输出和存储。例如，把一组考试成绩读入后求平均分，再把结果写入文件。
- **可编程性**体现为可以通过编写指令改变计算机完成的任务。同一台计算机可以运行计算器、文本编辑器和绘图程序，差异主要来自执行的程序。

**程序**是一组按照一定规则组织起来的指令。**程序设计**则是围绕任务组织这些指令的过程，包括理解需求、设计方法、编写代码和检验结果。代码能够运行，说明它通过了执行所需的部分检查，是否完成任务还要回到原始需求判断。需求理解有误时，程序也可能正常运行，却算出与目标无关的结果。

例如，“找出成绩优秀的学生”还不足以直接形成处理规则。需要进一步确定总分达到多少算优秀，是否要求每门课达标，以及缺考记录如何处理。这些条件明确后，程序才能逐条比较成绩，选出符合条件的学生。

### 1.2 编程语言的层次

编程语言用于表达数据和处理步骤。按表达方式与硬件细节的接近程度，可以先认识机器语言、汇编语言和高级语言。

<details>
<summary>术语解释：CPU、指令集与程序中的基本成分</summary>

**CPU**（Central Processing Unit，中央处理器）是执行机器指令的主要部件。**指令集**规定处理器支持哪些指令，**助记符**是指令的易读写法。

**变量**是引用数据的名称，**表达式**是能够计算出一个值的代码，**函数**是可以调用来完成一项功能的程序单元。例如，`2 + 3` 是表达式，`sum(...)` 是调用求和功能。这些概念会在第2章和第6章结合代码展开。

</details>

| 层次 | 主要表示方式 | 与硬件的关系 | 初学时应理解的内容 |
| --- | --- | --- | --- |
| 机器语言 | 机器指令的二进制编码 | 依赖具体指令集 | CPU执行的指令具有特定编码 |
| 汇编语言 | 用助记符表示指令 | 通常依赖具体指令集 | 需要汇编器转换为机器代码 |
| 高级语言 | 用变量、表达式、函数等描述计算 | 源代码通常具有更好的可移植性 | 便于人类表达算法和组织程序 |

这里的“高级”描述抽象层次。使用高级语言时，程序员可以直接表达变量、计算公式和循环等逻辑，许多底层指令与存储细节由语言实现和运行环境处理。因此，同一任务通常更容易用接近问题本身的方式描述。

**语言生态**指围绕一门语言形成的库、工具和开发者资源。它描述可利用的配套资源，不是与机器语言、汇编语言、高级语言并列的语言层次。Python属于高级语言，也拥有丰富的语言生态。

<details>
<summary>术语解释：内置、库、导入、实参与返回值</summary>

**内置**表示Python预先提供、可直接使用。**库**是一组可复用功能的统称，标准库随Python提供，第三方库通常需要另外安装。**导入**是用 `import` 等语句把模块或其中的名称引入当前程序。模块是组织Python功能的单元，简单的自建模块通常对应一个 `.py` 文件。

**实参**是调用时实际交给函数的数据，**返回值**是函数交回调用处的结果。`sum([2, 3])` 中的 `[2, 3]` 是实参，计算得到的 `5` 是返回值。屏幕显示什么，还要看是否执行了 `print()` 等输出操作。

</details>

例如，Python提供了内置求和函数 `sum()`，无需导入即可调用。它接收一个可迭代对象，也就是能够逐项取出元素的对象，再对其中的数值求和。把2和3组织成列表后，就可以把这个列表作为实参传给 `sum()`。

```python
result = sum([2, 3])
print(result)  # 5
```

方括号中的 `[2, 3]` 是一个列表，按顺序保存两个整数元素。`sum()` 对这些元素求和，返回值为5，再由内置函数 `print()` 输出。**直接写 `sum(2, 3)` 会因第一个实参2无法逐项遍历而引发类型错误。**使用现成函数时，既要理解用途，也要核对它对实参的要求。

> **学习提示**：这里把列表当作“按顺序放好的一组数据”即可。遍历见[第5章第5节](第5章_程序的控制结构.md#5-for-遍历循环)，列表内容修改见[第6章第6节](第6章_函数定义与调用.md#6-作用域名称绑定和对象修改)。列表的完整操作不在本笔记中集中讲解，后文会在用到时说明。类型错误属于异常，也就是操作无法按正常路径完成时报告的信号。异常处理见[第5章第3节](第5章_程序的控制结构.md#3-异常处理的执行路径)。

### 1.3 自然语言需求需要进一步明确

日常表达可以依靠上下文理解，程序则需要明确的处理规则。例如，“输出比较大的数”需要先说明比较哪些数。如果任务是输入两个数并输出最大值，还应确定相等时怎样显示结果。把这些约定写清楚，才能避免不同理解产生不同程序。

理解程序时可以反复检查三个问题。

1. 数据从哪里来，具有怎样的格式。
2. 每一步处理使用了什么规则。
3. 结果应以怎样的形式交给使用者。

把这三个问题分别写成输入、处理和输出，就形成了**IPO分析**。IPO取自Input（输入）、Process（处理）、Output（输出），本章第4节会用具体需求说明怎样分析。

## 2. Python语言与计算生态

### 2.1 Python的基本特点

Python由吉多·范罗苏姆（Guido van Rossum）设计和推动发展，下面的语法与示例采用Python 3。阅读资料或运行已有代码时，应先确认版本。Python 2与Python 3在部分语法和行为上存在区别，一段代码能否执行，需要以当前解释器支持的规则为准。

这里的**解释器**是负责执行Python代码的软件。**缩进**指代码行开头的空格，Python用它表示哪些语句属于同一组。下列特点中提到的过程式组织围绕处理步骤和函数展开，面向对象组织则围绕数据对象及其操作展开，本笔记以基本语法和函数为主。

Python的主要特点可以结合使用场景理解。

- **通用性**。可以编写数据处理、自动化、网络服务和科学计算等多类程序。
- **语法简洁**。用相对直接的语法表达计算，并通过缩进组织代码块。
- **生态丰富**。可以复用标准库与第三方库提供的功能。
- **跨平台**。许多Python程序可以在不同操作系统的合适运行环境中执行。
- **支持多种编程范式**。可以采用过程式、面向对象等方式组织代码。编程范式描述组织程序和表达计算的方法，一个程序也可以结合多种方式。

**跨平台运行需要目标环境提供合适的Python解释器和依赖库。**程序使用的文件路径、系统命令和其他接口，也需要适合目标操作系统。迁移程序时，可以逐项检查这些条件，再用实际运行结果确认兼容性。

### 2.2 标准库和第三方库

**标准库**随Python发行，提供数学、时间和文件处理等基础能力，例如 `math`、`time` 和 `datetime`。**第三方库**由生态中的开发者提供，通常需要另行安装。数据分析、绘图等任务中使用的许多工具都属于这一类。区分两者，有助于判断程序运行前需要准备哪些依赖。

“善用生态”可以落实为一个具体过程。

1. 明确需要完成的功能，例如获取当前日期。
2. 查找是否已有合适的标准库或第三方库。
3. 理解函数的输入、返回值和使用条件。
4. 在自己的程序中调用，并检查实际结果。

库通过接口向调用者提供功能。**对于一个函数，接口说明函数名、可接受的实参、返回值和使用条件。**前面的 `sum()` 就要求把待求和的数据放在可迭代对象中传入。理解这些约定后，才可以把库功能接入自己的程序。

代码量和运行速度需要结合具体任务判断。同一项功能，使用现成库可能只需几行调用代码，自行实现则可能需要更多步骤。程序的算法、实现方法、依赖库和运行环境也会影响结果，因此应通过具体程序比较表达成本与执行效率。

## 3. Python开发环境与运行方式

### 3.1 解释器、编辑器和开发环境

编写和运行程序时，会接触三类工具。**Python解释器**负责执行程序。**编辑器**用于输入和修改源代码，也就是人能够阅读的程序文本。**集成开发环境**（Integrated Development Environment，简称IDE）把代码编辑、运行和调试等功能组织在一起，方便在同一界面完成这些操作。调试就是跟踪程序执行，定位并修复错误。

**IDLE**（Integrated Development and Learning Environment）是Python提供的轻量集成开发与学习环境，包含交互环境和文件编辑器。**VS Code**（Visual Studio Code）是可扩展的代码编辑器，配置Python支持后也可以完成编辑、运行与调试。**Anaconda**是面向数据科学的Python发行方案，集成了常用软件包和环境管理工具。它们是可选工具，不需要全部安装。

使用VS Code时，关键是选择与当前项目对应的Python解释器。编辑器提供代码编辑界面，实际执行仍需要可用的解释器。安装方式会随操作系统和发行方案变化，可以先确认解释器能正常运行，再在编辑器中选择它，并用一个简单程序检查配置。

### 3.2 交互式运行

交互式运行是输入一段代码后立即执行，再继续接收下一段代码的方式。它适合试算表达式、观察结果和验证语法。Python交互环境通常用 `>>>` 提示当前可以输入代码。

```text
>>> 2 + 3
5
>>> radius = 2
>>> radius * radius
4
```

`>>>` 是交互环境显示的提示符，用户在它后面输入代码。把同样的计算保存为程序文件时，应保留 `2 + 3` 等代码本身。

<details>
<summary>术语解释：对象、引用与绑定</summary>

**对象**是Python表示数据的基本单位，例如整数 `2` 和字符串 `"Lin"` 都是对象。**字符串**是一段有顺序的文本，源代码中通常用引号界定。名称能找到一个对象，就说它**引用**该对象。赋值让名称与对象建立关联，这种关联称为**绑定**。

`radius = 2` 可以先读成“让名称 `radius` 指向整数2”。赋值规则见[第2章第2节](第2章_基本语法元素.md#2-变量命名保留字与赋值)，重新绑定与修改对象的区别见[第6章第6节](第6章_函数定义与调用.md#6-作用域名称绑定和对象修改)。

</details>

交互式环境会自动显示许多表达式的结果，所以输入 `2 + 3` 后能直接看到5。**赋值语句 `radius = 2` 把名称绑定到整数对象2，通常没有自动显示的结果。**之后输入 `radius * radius`，才会看到表达式的计算值4。

### 3.3 文件式运行

文件式运行把多条语句保存为通常以 `.py` 结尾的文本文件，再交给解释器执行。它适合保存、修改和重复运行完整程序。

```python
radius = 2
area = 3.1415 * radius * radius
print(area)
```

程序先把半径2赋给 `radius`，再计算面积并赋给 `area`，最后调用 `print()` 输出结果。**文件式运行通常不会自动显示单独表达式的值。**如果最后一行只写 `area`，计算结果仍然存在，但控制台通常看不到它，因此需要明确安排输出。

可以在配置好的开发环境中使用运行按钮，也可以在终端中调用相应解释器运行文件。例如，某些系统的命令为 `python3 circle.py`。实际命令名称和工作目录需要与本机环境一致。

<details>
<summary>术语解释：终端、控制台与工作目录</summary>

**终端**是输入命令、启动程序并查看输出的界面。这里的**控制台**指程序接收键盘输入和显示文本的区域，可能位于终端中，也可能位于开发工具内。**工作目录**是程序当前处理相对文件路径时使用的基准目录，不一定等于代码文件所在目录。

</details>

### 3.4 初次运行应检查什么

- 文件是否保存，扩展名是否正确。
- 编辑器选中的解释器是否可用。
- 源代码中的引号、括号和运算符是否使用正确字符。
- 程序是否正在等待输入。
- 错误信息指向哪一行，提示了哪类问题。

例如，程序停在 `input()` 处通常表示正在等待用户输入。此时应在运行控制台输入数据并按回车。

## 4. IPO方法与解决问题的步骤

### 4.1 IPO的含义

**IPO**分别取自Input、Process、Output，即输入、处理和输出。用IPO分析需求，就是先写清要提供哪些数据、怎样处理这些数据，以及最后交付什么结果。

| 部分 | 需要确定的内容 | 圆面积示例 |
| --- | --- | --- |
| 输入 | 数据的获取方式、类型、范围和格式 | 半径，约定为非负数 |
| 处理 | 从输入得到结果的规则 | 计算 `pi * r * r` |
| 输出 | 结果的含义、单位和显示格式 | 圆面积，保留两位小数 |

输入可以来自键盘、文件、网络或函数调用时传入的实参，也可以是写在程序中的固定数据。输出可以显示在控制台，写入文件，返回给调用者，或者绘制成图像。

分析IPO时，应沿着数据的流向判断每一部分。**固定半径也可以作为计算的输入，写入文件的面积也属于输出。**`input()` 和 `print()` 是实现输入输出的常用函数，完整的IPO范围还取决于程序承担的任务。

### 4.2 从模糊需求到具体IPO

假设需求是“统计本班平均成绩”。可以逐步明确。

1. 统计哪一次考试，哪些学生属于本次统计范围。
2. 每名学生有几个成绩字段，是否包含缺考记录。
3. 平均分使用全部学生人数还是有效成绩人数。
4. 最终输出一个数，还是同时输出人数和最高分。

统计范围和缺考规则确定后，才可以据此计算。例如，有效成绩为80、90、100，共3人，则总分为270，平均分为270除以3，得到90。如果缺考者也计入人数，分母就可能改变。平均分公式很简单，程序是否符合需求，仍取决于数据和人数的确定方式。

### 4.3 六个步骤

1. **分析问题**。识别问题中能够用明确规则进行处理的部分，理解任务目标。
2. **划分边界**。确定本次程序负责的范围与IPO约定。例如，本次只处理用户键盘输入，不处理图片中的成绩识别。
3. **设计算法**。决定怎样把输入转换为输出，必要时先写伪代码或流程图。
4. **编写程序**。将算法表达为Python代码，并采用合适的数据表示。
5. **调试测试**。观察执行过程，修复错误，用普通值和边界值检查结果。
6. **升级维护**。当输入格式、需求或运行环境变化时，调整程序。

这六个步骤并非只执行一遍。测试时如果发现空数据无法处理，就需要回到边界分析，确定应当拒绝输入还是输出特定结果。也可以把总体过程概括为“确定IPO、编写程序、调试程序”三个阶段，其中仍然包含算法设计。需求变化后，还要重新检查原来的输入约定和处理逻辑。

其中，**伪代码**是用接近自然语言的步骤描述算法，不要求能够直接运行。**流程图**用图形和箭头表示步骤及其先后关系。本章第5节会给出这两种表示。

### 4.4 测试怎样避免只看一个例子

以圆面积程序为例，半径0可以检查零值边界，半径1便于核对面积是否接近圆周率，带小数的半径可以检查数值读取与显示。测试非法输入前，也要先确定输入约定。题目保证合法输入时，可以在该范围内求解。面向一般用户时，则应说明负数和非数字文本怎样处理。

**运行一次得到预期结果，只说明该次输入下结果符合预期。**程序正确性还需要结合算法推理、代码检查以及更多有针对性的测试判断。

## 5. 算法、流程图与三种控制结构

### 5.1 算法表达解决方法

**算法**是完成特定计算的一组有限、明确且可以执行的指令。算法需要说明每一步做什么，以及步骤之间怎样衔接。阅读时可以先找输入和输出，再检查处理过程能否在约定条件下结束。

“把1到n全部加起来”还可以继续细化为下面的算法。这里约定n为正整数。

```text
读取n
令total为0
依次取出1到n的每个整数i
    把i加到total中
输出total
```

当n为3时，`total` 初始为0。加入1后变成1，再加入2后变成3，最后加入3后变成6。把每次更新写出来，就能核对“依次累加”的描述究竟怎样执行，也能发现是否遗漏了某个整数。

同一任务可以采用不同算法。求1到n的和，除了循环累加，也可以利用公式 `n * (n + 1) // 2`。循环需要逐个处理整数，公式则直接使用n计算。**对正整数n，两种方法的结果一致，但执行的步骤数量不同。**选择算法时，应同时考虑正确性、效率、输入范围和表达是否清楚。

> **学习提示**：公式中的 `*` 表示乘法，`//` 表示向下取整除法。本例分子能被2整除，所以结果恰好是整数和。运算规则见[第3章第5节](第3章_数字类型与运算.md#5-算术运算与表达式顺序)，循环写法见[第5章第5节](第5章_程序的控制结构.md#5-for-遍历循环)。

### 5.2 流程图的基本符号

| 符号用途 | 常见形状 | 表达的含义 |
| --- | --- | --- |
| 起止框 | 椭圆或圆角框 | 算法开始与结束 |
| 处理框 | 矩形 | 计算、赋值等操作 |
| 输入输出框 | 平行四边形 | 读入或输出数据 |
| 判断框 | 菱形 | 根据条件选择路径 |
| 流向线 | 带箭头的线 | 步骤执行方向 |

阅读流程图时先找到开始，沿箭头跟踪。经过判断框时，要根据当前变量值选择相应分支。若箭头返回先前步骤，需检查循环何时结束。

### 5.3 顺序、分支与循环

**顺序结构**让语句按照规定次序依次执行。例如，先读取半径，再计算面积，最后输出。

**分支结构**根据条件选择执行路径。例如，摄氏温度采用一种公式，华氏温度采用另一种公式。分支中的条件需要能够判断真或假。

**循环结构**重复执行一组步骤。例如，对每个学生的成绩进行加总，或者连续产生斐波那契数列的下一项。

**这三种结构可以嵌套和组合。**求一组成绩中的及格人数时，通常先用循环逐个取成绩，再用分支判断该成绩是否达到及格线。

阅读具体程序时，可以先判断当前语句属于顺序、分支还是循环，再沿着实际执行路径追踪。结构名称帮助概括计算方式，变量值则决定每一步真正发生什么。

## 6. 计算思维中的抽象与自动化

**抽象**是从实际问题中选取与计算目标有关的信息，建立可处理的数据与规则。例如，计算圆面积时，可以保留半径这个量，并使用圆面积公式。圆的颜色和绘制工具通常与面积计算无关。

**自动化**是把这些规则表达成计算机能够执行的步骤，再由计算机反复完成处理。例如，处理一千个圆的面积时，可以把相同计算规则应用到每个半径。

把抽象与自动化结合起来，可以形成下面的问题求解过程。

1. 从现实需求中选取与目标相关的信息。
2. 用数字、字符串等形式表示这些信息。
3. 设计明确的计算步骤。
4. 编写和运行程序。
5. 检查结果是否仍符合原来的现实需求。

逻辑思维关注推理与演绎，实证思维关注观察和实验，计算思维关注如何把问题表达为可自动执行的过程。实际问题求解中，这些方法经常结合使用。算法正确性需要推理，性能观察需要实验，模型选择还需要领域知识。

练习阅读程序时，可以先预测输出，再运行核对。预测与结果不一致时，按执行顺序记录变量值，找出从哪一步开始产生差异。这样能够逐步建立对语句和控制结构的理解。使用工具辅助生成代码后，也应采用同样的方法，检查需求、输入输出和执行逻辑。

## 7. 四个微实例的逐步理解

> **学习提示**：这四个实例用于观察“输入、计算、输出”怎样连接。先跟着变量变化读懂结果，遇到格式化、循环和模块调用时，可按各例后的提示返回对应章节学习。

### 7.1 根据半径计算圆面积

圆面积由半径决定，计算公式可以写为 `area = pi * radius * radius`。下面把半径设为25，用3.1415近似表示圆周率，并分别观察普通输出和保留两位小数的输出。

```python
radius = 25
area = 3.1415 * radius * radius
print(area)
print("{:.2f}".format(area))
```

第一行给半径命名为 `radius`，并赋值25。第二行先计算右侧的乘积，再把面积结果赋给 `area`。第三行把数值转换为通常的显示形式后输出。第四行使用模板 `{:.2f}` 生成保留两位小数的字符串，因此显示为1963.44。计算、保存结果和安排显示格式是先后发生的操作。

应区分“计算得到的数值”和“显示给人的形式”。**第四行生成用于输出的字符串，变量 `area` 仍引用原来的数值对象。**程序使用的3.1415是圆周率的近似值，因此计算结果也带有近似性。选择常量精度与输出位数时，应结合任务要求。

<details>
<summary>术语解释：字符串、方法与格式化</summary>

**字符串**是按顺序排列的文本，通常用引号表示。**方法**是通过对象访问的功能，例如 `"{:.2f}".format(area)` 调用这个字符串的 `format()` 方法。**格式化**是按要求组织文本的显示形式。这里先记住 `{:.2f}` 表示把数值显示为两位小数。

输入输出的基本用法见[第2章第5节](第2章_基本语法元素.md#5-基本输入与数值转换)、[第2章第6节](第2章_基本语法元素.md#6-输出与格式化显示)，字符串方法和完整格式规则见[第4章第4节](第4章_字符串与time库.md#4-常用字符串方法)、[第4章第5节](第4章_字符串与time库.md#5-字符串格式化)。

</details>

### 7.2 姓名输入与回应

输入姓名属于读取文本的任务。可以先用 `input()` 接收用户输入，再把得到的姓名放进固定的问候语中。

```python
name = input("Please enter your name: ")
print("Hello, {}".format(name))
```

`input()` 是可以直接调用的内置函数。它先输出实参中的提示文本，再等待输入。用户按回车后，函数返回输入字符串，并将它赋给 `name`。第二行中，`{}` 是模板里留出的替换字段，模板字符串的 `format()` 方法把 `name` 引用的字符串作为实参，填充这个位置，再由 `print()` 输出生成的字符串。例如输入 `Lin`，就会输出 `Hello, Lin`。

还可以使用 `name[0]` 取第一个字符，用 `name[1:]` 取后续字符。**使用 `name[0]` 需要姓名字符串非空，否则会发生索引错误。**按第一个字符划分姓氏也有适用条件，复姓等情形需要另设规则。字符位置可以直接确定，姓名结构则取决于实际的数据约定。

> **学习提示**：`name[0]` 是按位置取字符的“索引”，`name[1:]` 是截取一段内容的“切片”。此处先理解用途，完整规则见[第4章第2节](第4章_字符串与time库.md#2-索引与切片)。

### 7.3 斐波那契数列与同步更新

> **学习提示**：本例提前使用 `while` 循环和解包赋值。现在只需跟踪表格中的两个数，解包赋值见[第2章第2节](第2章_基本语法元素.md#2-变量命名保留字与赋值)，`while` 的执行规则见[第5章第6节](第5章_程序的控制结构.md#6-while-条件循环)。

这里采用从1、1开始的斐波那契数列，此后每一项都等于前两项之和。因此，前几项是1、1、2、3、5、8。要连续产生这些项，只需保存相邻的两个数，每次输出当前项，再计算下一项。

```python
a, b = 1, 1
while a <= 1000:
    print(a, end=",")
    a, b = b, a + b
```

初始时 `a` 和 `b` 都为1，分别保存相邻的两项。`while` 每轮先判断当前的 `a` 是否不大于1000，成立时输出它，再更新两个变量。`end=","` 把每次输出的末尾设为逗号，因此各项连续显示在同一行，最后一项后也会留下逗号。

| 本轮开始的a | 本轮开始的b | 输出 | 本轮更新后的a | 本轮更新后的b |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 1 | 2 |
| 1 | 2 | 1 | 2 | 3 |
| 2 | 3 | 2 | 3 | 5 |
| 3 | 5 | 3 | 5 | 8 |

**`a, b = b, a + b` 会先用本轮开始时的值计算右侧。**若旧值为2和3，右侧先得到3与5，再分别赋给左侧的 `a` 和 `b`。因此，新 `a` 是原来的后一项，新 `b` 是原来两项之和，相邻关系得以保持。

如果改成先执行 `a = b`，再执行 `b = a + b`，第二条语句就会使用已经改变的 `a`。例如旧值为2和3时，先把 `a` 改成3，随后相加得到6，便无法产生应有的下一项5。

**条件 `a <= 1000` 直接对应“不大于1000”，包含端点1000。**若写成 `a < 1000`，则表示严格小于1000。对这个特定数列，两种条件恰好得到相同输出，因为1000本身并非其中一项。换成其他上限时，端点是否属于数列就可能改变输出，编写条件时应始终核对需求。

### 7.4 输出当前日期与时间

<details>
<summary>术语解释：模块、类与实例</summary>

**模块**是组织Python功能的单元，简单的自建模块通常就是一个 `.py` 文件。**类**描述一类对象的数据和操作，按这个类得到的具体对象称为它的**实例**。此例的 `datetime` 模块中恰好有一个也叫 `datetime` 的类，`now` 保存该类的一个日期时间实例。

导入语法见[第2章第9节](第2章_基本语法元素.md#9-模块导入的三种基本方式)。[第4章第7节](第4章_字符串与time库.md#7-时间表示utc与本地时间)至第9节会讲 `time` 模块及时间格式化，但不会逐项介绍 `datetime` 类。类的自行定义也不在这七章的范围内。

</details>

日期时间可以先用一个对象表示，再按需要输出为完整时间、日期或时分秒。标准库模块 `datetime` 中的 `datetime` 类提供 `now()`，用于获取本地当前时间。取得对象后，可以调用它的 `strftime()` 方法，按模板生成字符串。

```python
from datetime import datetime

now = datetime.now()
print(now)
print(now.strftime("%Y-%m-%d"))
print(now.strftime("%H:%M:%S"))
```

导入语句使名称 `datetime` 引用标准库模块中的同名类。调用 `datetime.now()` 后，变量 `now` 引用这一次返回的日期时间对象。`print(now)` 输出其通常形式，后两行则分别调用同一个对象的 `strftime()` 方法，生成并输出日期字符串和时间字符串。

**程序只调用一次 `now()`，所以后续输出使用同一个时间值。**再次运行时，输出会随系统时间变化。模板 `%Y-%m-%d` 明确表示年月日，`%H:%M:%S` 明确表示时分秒。另一组控制符 `%x`、`%X` 分别表示本地区域设置下的日期和时间形式，显示方式可能随环境变化。

## 8. 编译、解释与类型检查的区别

源代码需要经过相应的语言实现才能执行。理解这个过程时，应把两个问题分开。一个是代码通过什么机制运行，另一个是类型规则在什么时候、按什么方式检查。编译与解释主要讨论前者，静态类型与动态类型主要讨论后者。

### 8.1 编译和解释关注执行机制

**编译**是把一种程序表示转换为另一种表示的过程，完成这一转换的工具称为编译器。编译结果可以是CPU能够执行的机器代码，也可以是交给后续运行环境处理的字节码等中间表示。理解“编译”时，要同时看转换前后分别是什么。

**解释**是由解释器或虚拟机读取程序表示，按照相应规则完成操作。“边翻译边执行”可以帮助形成初步印象，实际实现则可能先进行分析、编译或优化，再执行得到的表示。

<details>
<summary>术语解释：字节码、虚拟机、CPython与即时编译</summary>

**字节码**是供特定运行环境处理的中间指令表示。**虚拟机**在这里指执行这类指令的软件机制。**CPython**是主要用C语言编写的Python实现，也是常见的Python解释器。

**即时编译**（Just-in-Time compilation，JIT）是在程序运行时把部分代码编译成更便于机器执行的形式。这些概念用于区分执行机制，本笔记不展开解释器和编译器的内部实现。

</details>

两种机制能够组合使用。**常用Python实现CPython会先把源代码编译为字节码，再由其虚拟机执行字节码。**Java的常见执行过程也包含先编译为字节码，再由运行环境解释或即时编译等环节。

常见的“解释型语言”称呼概括了运行方式，但具体执行过程仍要看所用实现。CPython的过程同时包含编译和字节码执行，也说明编译产生的目标表示可以继续由虚拟机处理。

### 8.2 静态类型和动态类型关注类型检查

**静态类型**通常在运行前检查类型使用关系。**动态类型**则在运行过程中，根据实际对象的类型判断操作是否适用。两者讨论类型规则，与代码采用编译还是解释执行属于不同维度。

Python通常归入动态类型语言。对象具有类型，变量名通过绑定引用对象。同一个名称可以先引用整数，之后再引用字符串。**名称能够重新绑定，具体对象支持哪些操作仍由其类型决定。**

```python
value = 10
print(value + 2)
value = "ten"
print(value)
```

程序依次输出12和 `ten`。同一个名称在两个时刻引用了不同类型的对象。

第一条加法执行时，`value` 引用整数10，因此可以与整数2相加。重新赋值后，`value` 引用字符串 `"ten"`，原来已经输出的12不会改变。若接下来还要运算，就需要按字符串的规则判断。

“脚本”通常用来描述服务于自动化等任务的程序及其使用方式，也带有历史习惯。理解一个程序时，仍应分别确认它的执行机制和类型规则。

### 8.3 性能与可移植性需要结合条件

**运行时**指支撑程序执行的软件环境与机制，**依赖**指程序运行所需的其他模块、库或工具。可移植性表示程序迁移到另一环境时能够继续运行的程度。

编译优化可能改善运行速度，解释器和运行时也会带来执行开销。但程序实际性能还受到算法、数据规模、底层库和实现方式影响。Python调用的某些计算库本身就使用编译代码。

可移植性则取决于目标环境能否提供程序所需的运行时、依赖库和系统接口。判断实际程序时，可以分别检查算法与执行效率，以及依赖与运行条件，避免用一个笼统结论代替具体分析。

## 参考答案与解析

**第1题 B**

同一设备可以执行不同的指令序列，从而完成不同任务，这体现了可编程性。计算、输入输出和存储等能力则体现了功能性。

**第2题 A**

程序设计需要先理解任务，再设计求解方法、编写代码并检查结果。语法正确和能够运行是必要的检查内容，任务是否完成还取决于结果是否符合需求。

**第3题 C**

汇编语言使用助记符表达与具体指令集有关的指令，通常由汇编器转换成机器代码。流程图则描述算法步骤和执行路径。

**第4题 D**

使用库函数时，需要核对实参是否符合要求、返回值是什么以及适用条件。标准库随Python发行，第三方库通常需要另行安装。生态提供了现成功能，正确调用仍需要理解接口。

**第5题 A**

`>>>` 是交互环境显示的提示符，表示可以在后面输入代码。保存程序文件时，只需写入实际代码。

**第6题 C**

第一行计算并保存5，第二行单独写出变量名，文件式运行时通常不会自动显示它。第三行调用 `print(x)`，因此控制台只输出一行5。

**第7题 B**

成绩相加再除以人数，是把原始数据转成平均分的处理过程，对应Process。原始成绩属于输入，最后交付的平均分属于输出。

**第8题 D**

缺考记录是否计入会影响总分、人数或两者，因此可能改变平均分。应先明确统计口径，再据此编写计算规则。

**第9题 B**

六步骤通常依次为分析问题、划分边界、设计算法、编写程序、调试测试、升级维护。实际工作中也可能回到前面修订。

**第10题 A**

半径0检查零值边界，半径1便于核对公式，小数半径检查数值处理。这些输入针对不同情况设计，比只观察一次运行更有助于发现问题。

**第11题 D**

菱形表示条件判断，执行时根据条件选择路径。输入输出常用平行四边形，处理常用矩形。

**第12题 C**

逐个取出成绩需要重复执行，因此使用循环。每次再根据是否达到及格线决定要不要累计，使用的是分支。

**第13题 C**

抽象要选取与目标相关的信息。圆面积公式依赖半径，在该任务中通常不需要圆的颜色。

**第14题 B**

字符串的 `format()` 方法根据实参12.566返回字符串 `"12.57"`，再由 `print()` 输出。代码没有重新给 `area` 赋值，因此它保存的数值仍是12.566。

**第15题 A**

右侧先使用旧值2和3，得到3与5，再依次赋给左侧的 `a` 和 `b`。因此更新后 `a` 为3，`b` 为5。

**第16题 D**

`name[0]` 要访问位置0，字符串中必须至少有一个字符。取得第一个字符只能确定字符位置，是否对应完整姓氏还要结合复姓等实际情况判断。

**第17题 D**

CPython通常先把源代码编译为字节码，再交给虚拟机执行。这个过程同时包含编译和执行中间表示两个环节。

**第18题 C**

静态类型与动态类型主要涉及类型规则的检查和使用方式。编辑器、文件后缀或注释使用的文字，都不能据此确定类型系统。

**第19题 B**

可移植程序仍依赖运行环境和所调用的功能。路径、系统接口和第三方库都可能影响跨平台运行。

**第20题 A**

先取得一次当前时间并保存为对象，后续日期和时分秒都从这个对象生成，就能对应同一时刻。每次重新运行程序时，取得的时间仍会随系统时间变化。
