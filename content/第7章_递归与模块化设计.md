# 第7章 递归与模块化设计

递归把一个问题转化为同类的较小问题，模块化设计把一个较大任务拆成职责明确的功能单元。本章先用阶乘、字符串反转和斐波那契数列解释递归，再介绍代码复用与模块接口，最后用人工智能（Artificial Intelligence，简称AI）问答和股票数据处理两个完整实例说明多个函数如何协作。

学完本章，应能说明递归何时结束、返回值怎样逐层传递，识别重复计算，并根据输入、返回结果和错误处理约定设计模块。汉诺塔和数据分析部分提供了进一步练习递归分解与流程组织的实例。

> **学习提示**：第1至第4节是递归核心内容，第5节是汉诺塔拓展，第6节讲模块协作。第7、第8节是综合应用，先沿输入、返回值和函数调用理解流程即可，字典、推导式与第三方库的新用法会就近补充。外部接口与数据分析工具没有后续专章，本章只解释读懂这些案例所需的部分。

## 1. 递归怎样描述问题

### 1.1 把同类小问题交给函数自身

在函数体中调用函数自身，就形成了直接递归。例如阶乘可以按以下规则定义。

- 当 `n = 0` 时，`n! = 1`。
- 当 `n > 0` 时，`n! = n × (n - 1)!`。

第二条规则把计算 `n!` 转化为先计算 `(n - 1)!`，再乘以 `n`。两次计算都属于求阶乘，只是输入大小不同，因此函数可以调用自身来处理较小输入。

```python
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)
```

这个函数约定输入为非负整数。`n == 0` 对应**递归基例**（base case），也就是无需再调用自身便能直接求解的情形。`n > 0` 时进入递归链条，通过较小问题的结果构造当前问题的结果。

**从非负整数出发，每次递归让 `n` 减1，经过有限次调用就会到达0。**这个变化过程解释了函数为什么能够结束。

### 1.2 基例存在，还要保证能够到达

下面的写法虽然出现了基例，递归过程却持续远离基例。

```python
def bad_factorial(n):
    if n == 0:
        return 1
    return n * bad_factorial(n + 1)
```

从正整数开始调用时，形参 `n` 的值不断增大，最终通常会引发 `RecursionError`。类似地，把负数传给前面的 `factorial`，形参 `n` 的值会不断减小，也无法到达0。

因此写递归函数时，应同时检查三项内容。

1. 输入范围是否明确。
2. 哪些输入可以直接返回结果。
3. 每次递归调用是否让问题按某个可衡量的尺度缩小，并最终进入基例。

衡量问题大小的尺度可以是整数值、字符串长度或待处理元素个数。**常用的做法是让它取非负整数值，并在每次递归时严格减小，再为最小情形定义基例。**这样就能说明调用会在有限步内结束。

### 1.3 与数学归纳法的联系

数学归纳法先验证起始情形，再证明较小情形成立时较大情形成立。递归程序则先定义基例，再在计算较大输入时调用较小输入的函数。

两者都利用同类问题之间的结构关系。用递归写程序时，可以先假设递归调用能正确返回较小问题的结果，再考虑当前这一层如何加工这个结果。例如只要 `factorial(n - 1)` 正确，乘以 `n` 就能得到 `factorial(n)`。

分析递归函数的正确性时，应把三个环节连起来。基例给出的结果要正确，递归步骤要能用较小问题的结果构造当前结果，调用过程还要在有限步内到达基例。

## 2. 阶乘递归的展开与返回

### 2.1 调用向下展开

计算 `factorial(4)` 时，各层表达式依次为以下形式。

```text
factorial(4) 等待 4 * factorial(3)
factorial(3) 等待 3 * factorial(2)
factorial(2) 等待 2 * factorial(1)
factorial(1) 等待 1 * factorial(0)
factorial(0) 返回 1
```

计算 `4 * factorial(3)` 时，需要先取得 `factorial(3)` 的返回值，才能完成乘法。调用下一层时，当前层会保留自己的形参绑定和待完成的操作。表中的“等待”就表示这种状态。

### 2.2 结果向上返回

到达基例后，计算按相反方向完成。

```text
factorial(0) 返回 1
factorial(1) 返回 1 * 1 = 1
factorial(2) 返回 2 * 1 = 2
factorial(3) 返回 3 * 2 = 6
factorial(4) 返回 4 * 6 = 24
```

每次调用都有自己的局部形参 `n`。例如，`factorial(4)` 保留的 `n` 为4，`factorial(3)` 保留的 `n` 为3。内层得到6并返回后，外层再用自己的4完成乘法。

这些尚未完成的调用由调用栈记录。**最后进入的一层先返回，随后逐层恢复外层的计算，这里称为逐层返回。**

<details>
<summary>术语解释：调用栈、栈帧与递归深度</summary>

**栈**是一种“后进先出”的组织方式。**调用栈**记录尚未完成的函数调用，一次调用所需的局部名称和执行位置等信息组成一个**栈帧**。**递归深度**表示递归调用同时嵌套了多少层。

本例中 `factorial(0)` 最后进入，最先返回。递归的逐层返回不等同于“回溯算法”，后者通常指尝试选择、撤销选择并搜索其他可能的算法，本章不展开该算法。

</details>

### 2.3 返回值必须沿链条传递

```python
def wrong_factorial(n):
    if n == 0:
        return 1
    n * wrong_factorial(n - 1)
```

最后一行计算了表达式，却没有返回它的结果。`wrong_factorial(1)` 先算出 `1 * 1`，然后运行到函数末尾，隐式返回 `None`。如果外层正在计算 `wrong_factorial(2)`，接下来就会尝试 `2 * None`，引发 `TypeError`。

写递归函数时，需要明确每一层交给调用者的结果。**可以直接用 `return` 返回包含递归调用的表达式，也可以先保存并加工子问题的结果，再显式返回。**

### 2.4 计算代价和递归深度

`factorial(n)` 从 `n` 一直调用到0，共执行 `n + 1` 次调用。到达基例时，这些调用同时保存在栈中。若把一次乘法视为一个基本操作，运算次数与调用栈空间都随 `n` 线性增长。

进一步分析真实运行时间时，还要考虑整数位数增长带来的大整数乘法开销。这里先用调用次数和递归深度比较算法的基本结构。

<details>
<summary>术语解释：线性、平方与指数数量级</summary>

这些说法描述输入规模 `n` 增大时，计算量的大致增长趋势。**线性**约随 `n` 增长，**平方**约随 `n²` 增长，**指数**则像 `2ⁿ` 那样让 `n` 出现在指数上。

这里比较的是约定了基本操作后的调用次数或字符处理量，不是精确耗时。完整的算法复杂度分析不在这七章中展开。

</details>

Python 3 的递归深度存在运行时限制。**输入较大时，即使数学上能够到达基例，也可能在实际执行中触及限制。**阶乘本身也可以用循环实现，循环版本便于避开逐层调用所需的栈空间。

## 3. 用递归反转字符串

### 3.1 分解规则

对非空字符串 `s`，把它拆成第一个字符 `s[0]` 和剩余部分 `s[1:]`。反转整个字符串，可以先反转剩余部分，再把原来的首字符接到最后。

```python
def reverse_text(s):
    if s == "":
        return s
    return reverse_text(s[1:]) + s[0]
```

空字符串直接返回自身，字符串长度每次减1，因此递归能够到达基例。

以 `"ABC"` 为例，展开过程如下。

```text
reverse_text("ABC") 等待 reverse_text("BC") + "A"
reverse_text("BC")  等待 reverse_text("C") + "B"
reverse_text("C")   等待 reverse_text("") + "C"
reverse_text("")    返回 ""
```

逐层返回时依次得到 `"C"`、`"CB"`、`"CBA"`。

### 3.2 切片、拼接和原字符串

字符串具有不可变性。递归过程中，`s[1:]` 取得剩余部分，`+` 生成拼接后的字符串。要在后续代码中使用反转结果，调用者需要接收函数的返回值。

```python
text = "Python"
reversed_text = reverse_text(text)
print(text)
print(reversed_text)
```

两行输出分别为 `Python` 和 `nohtyP`。

这个例子清楚地展示了递归结构，也包含额外的字符复制。常见字符串实现中，每层都要处理切片和拼接，相关长度依次接近 `n`、`n - 1`、一直到1。总字符处理量可按 `n + (n - 1) + ... + 1` 理解，达到平方数量级。

普通字符串反转可以直接使用 `s[::-1]`。理解递归写法时，则应逐步追踪剩余字符串如何变短、何时到达空串，以及逐层返回时字符如何拼接。

## 4. 斐波那契递归与重复计算

### 4.1 从数列定义写出函数

本章采用 `F(1) = F(2) = 1`，从第3项起 `F(n) = F(n - 1) + F(n - 2)`。

```python
def fibonacci(n):
    if n == 1 or n == 2:
        return 1
    return fibonacci(n - 1) + fibonacci(n - 2)
```

函数约定输入为正整数，前几项依次为1、1、2、3、5、8、13。斐波那契数列也可以从 `F(0) = 0`、`F(1) = 1` 开始定义，使用时要先明确下标与基例。

### 4.2 递归树中有相同子问题

**递归树**是把一次调用画成一个结点、把它发起的子调用画成下层分支的示意图，便于看出重复计算。它表示整个调用过程，调用栈则只保存当前尚未完成的那条调用路径。

计算 `fibonacci(5)` 时，需要 `fibonacci(4)` 和 `fibonacci(3)`。其中 `fibonacci(4)` 又需要 `fibonacci(3)` 和 `fibonacci(2)`。

这样，`fibonacci(3)` 会在不同分支中重复计算。**输入继续增大时，同类重复会越来越多，导致总调用次数呈指数数量级增长。**

阶乘每个非基例只产生一个较小调用，朴素斐波那契每个非基例产生两个调用。因此，分析递归代价时，需要同时观察递归深度、每层分支数，以及不同分支是否重复求解相同输入。

### 4.3 用循环保存已有结果

可以用两个变量保存相邻两项，每轮循环只计算下一项。

```python
def fibonacci_loop(n):
    a, b = 1, 1
    for _ in range(n - 1):
        a, b = b, a + b
    return a
```

输入仍约定为正整数。初始时 `a`、`b` 分别保存第1项和第2项。解包赋值先用旧值求出 `b` 和 `a + b`，再分别更新 `a`、`b`，使这一对相邻项向后推进一位。循环执行 `n - 1` 次后，`a` 保存第 `n` 项。

按一次加法计为一个基本操作，这个版本使用线性次数的加法，只需两个变量保存相邻项。保留递归形式时，也可以缓存已经求出的结果，让后续相同输入直接复用。两种思路都在减少对子问题的重复计算。

## 5. 汉诺塔的递归分解（拓展实例）

三根柱子分别承担源柱、目标柱和辅助柱的角色。初始时，`n` 个盘子在源柱上从上到下按从小到大的顺序叠放。每次只能移动一个盘子，移动后仍须保证大盘在小盘下方。

移动 `n` 个盘子可以拆成三步。

1. 把上方 `n - 1` 个盘子从源柱移到辅助柱，此时原目标柱作为辅助。
2. 把最大的第 `n` 个盘子从源柱移到目标柱。
3. 把 `n - 1` 个盘子从辅助柱移到目标柱，此时原源柱作为辅助。

```python
def hanoi(n, source, target, helper):
    if n == 1:
        print(source, target)
        return
    hanoi(n - 1, source, helper, target)
    print(source, target)
    hanoi(n - 1, helper, target, source)
```

这个版本约定 `n` 为正整数，每条输出给出一次移动的起点和终点。`source`、`target`、`helper` 表示当前子任务中的角色。第一轮递归要把小盘移到辅助柱，因此把原来的 `helper` 传给新的 `target`，其余角色也随任务调整。

记移动次数为 `T(n)`。一个盘子直接移动一次，因此 `T(1) = 1`。有多个盘子时，先后两次处理 `n - 1` 个小盘，中间移动一次大盘，所以 `T(n) = 2T(n - 1) + 1`，解得 `T(n) = 2 ** n - 1`。例如3个盘子需要移动7次。

还可以在移动时累计次数。如果采用全局名称 `count`，每次开始新的演示前应重新初始化它，否则不同演示的次数会累加。也可以让函数返回移动次数，由调用者接收结果，这样函数之间的依赖关系更加直接。

## 6. 代码复用、封装和模块化

### 6.1 抽象让调用者使用更高层的含义

循环中怎样更新两个变量，属于实现细节。调用者关心的是取得数列第 `n` 项。把更新过程放进 `fibonacci_loop(n)` 后，就可以通过函数名与实参表达这个计算任务。

复用一个函数，需要明确它接收什么输入、返回什么结果，以及会产生哪些额外操作。不同调用位置因此能够使用同一份实现，避免反复复制和修改相同逻辑。

封装把实现细节集中在明确的接口后面。**函数名、形参、返回值和使用条件共同构成调用约定。**调用者依照这些约定使用功能，内部实现则可以在满足同一约定的前提下调整。

### 6.2 函数、对象、模块的关系

- 函数把一个处理过程组织为可调用单元。
- 对象把相关数据和操作组织在一起，属性表示数据，方法表示相关操作。
- Python 3 模块通常对应一个 `.py` 文件，可以包含多个函数、类和模块级变量，供其他程序导入。

<details>
<summary>术语解释：Notebook与内核</summary>

**Notebook**是把说明文字和可分块运行的代码放在一起的交互文档，Jupyter Notebook是常见工具。**内核**（kernel）是实际执行其中代码的进程，会保留先前运行产生的变量。重启内核会清除这些运行状态。此处不要求改用Notebook，普通 `.py` 文件也能完成练习。

</details>

例如，把本章定义的 `reverse_text` 和 `fibonacci_loop` 保存到同一个 `study_tools.py` 文件中。另一个程序可以导入其中需要的函数。

```python
from study_tools import fibonacci_loop

print(fibonacci_loop(6))
```

使用前需要先保存 `study_tools.py`。入门练习时，可以让它与调用程序位于同一文件夹，再运行调用程序。解释器会按模块搜索路径查找文件。**模块搜索路径**是解释器寻找可导入模块时检查的一组位置。在Notebook中练习时还需核对当前工作目录。上面的调用输出8。

### 6.3 高内聚与低耦合

模块化设计强调**模块内部高内聚，模块之间低耦合**。

高内聚表示模块内部的功能围绕共同职责组织。例如，下载模块集中处理请求参数、获取响应和整理下载结果。低耦合表示模块之间通过清楚的接口协作，减少对彼此内部变量和实现步骤的依赖。

如果收益率函数只接收价格数据并返回计算结果，就可以使用人工构造的少量价格检查算法。若它同时读取全局账户信息、下载数据、修改图形设置，理解和单独验证都会更加困难。

模块之间仍需传递必要的数据。例如，下载函数把价格表交给计算函数，计算函数把收益率结果交给绘图函数。各方依赖的是约定好的数据结构，调用者能够据此连接流程。

### 6.4 主函数负责组织流程

一个任务可以先拆为获取输入、计算结果和展示结果几个步骤。**主函数安排先后顺序，并把每一步所需的数据交给对应函数。**

```python
def mean_value(values):
    return sum(values) / len(values)


def show_result(value):
    print("{:.2f}".format(value))


def main():
    values = [80, 90, 100]
    result = mean_value(values)
    show_result(result)


if __name__ == "__main__":
    main()
```

`mean_value` 约定输入为非空数值序列。主函数先准备三个成绩，再取得平均值90，最后调用展示函数输出 `90.00`。

末尾的条件控制程序入口。文件直接运行时，`__name__` 为 `"__main__"`，于是执行 `main()`。被其他程序导入时，`__name__` 通常为模块名称，调用者可以按需使用其中的函数。

## 7. AI 调用案例中的接口设计

这个实例把模型查询和文字问答封装成模块。程序需要先取得授权配置、建立客户端，再发送请求并读取响应。下面给出完整的最小实现，逐步说明这些操作如何分配到函数中。

### 7.1 运行条件与模块分工

**API**（Application Programming Interface，应用程序编程接口）约定请求和返回数据的形式，**SDK**（Software Development Kit，软件开发工具包）提供在本地调用接口的代码。这个实例使用适用于 Python 3 的 `openai` SDK，访问 SiliconFlow 的兼容 API，服务地址为 `https://api.siliconflow.cn/v1/`。客户端中的服务地址决定请求交给哪一家服务，服务端接收请求并返回响应。

<details>
<summary>术语解释：客户端、服务端、API密钥与软件包</summary>

**客户端**是发出请求的一方，这里指Python程序中管理请求的对象。**服务端**接收请求、完成处理并返回结果。**请求**是发送给服务的任务和数据，**响应**是服务返回的结果。

**API密钥**是服务用来识别和授权调用的凭据。本例使用的是目标服务的密钥。**软件包**是可安装、分发的一组代码，`pip` 是Python常用的软件包安装工具。此处安装 `openai` SDK并不决定请求一定发给OpenAI，请求目的地由客户端配置的服务地址决定。

</details>

服务端通过模型标识符区分模型，程序以字符串形式传递这些标识符。本地允许列表也称白名单，用于记录程序允许请求的模型标识符。

运行需要 Python 3 环境、`openai` 软件包、能够访问服务的网络，以及该服务有效的 API 授权和文字模型调用权限。先在执行程序所用的环境中安装软件包。

```bash
python -m pip install "openai>=1.0,<3"
```

使用 Notebook 时，应在当前内核对应的环境安装软件包。`%pip` 是 Notebook 提供的魔法命令，用于把安装操作交给当前内核的环境。终端安装则需要核对 `python` 指向的解释器。

```python
def get_models(client=None, task=None):
    if task is not None and task not in MODEL_GROUPS:
        raise ValueError("Unknown task")
    owns_client = client is None
    client = _get_client(client)
    try:
        available = [model.id for model in client.models.list().data]
        selected = [model for model in available if model in ALLOWED_MODELS]
        if task is not None:
            selected = [model for model in selected
                        if model in MODEL_GROUPS[task]]
        return selected
    finally:
        if owns_client:
            client.close()
```

函数先检查 `task` 是否属于已定义的任务组，再请求服务端模型列表。随后保留本地允许的模型标识符，提供 `task="chat"` 时，还会进一步保留文字任务分组中的模型标识符。

查询成功后返回模型标识符列表，可能包含多项，也可能为空。空列表表示本次筛选没有匹配项，调用者需要先判断是否为空，再按下标取出模型标识符。

`owns_client` 记录客户端是否由本次函数创建。**自行创建的客户端在查询结束后关闭，传入的客户端则继续由调用者管理。**`finally` 保证这一关闭操作在正常返回或查询出错时都会执行。

查询中发生认证、网络等错误时，异常会传给调用者。模型查询和后续问答是两次独立请求，调用者需要分别根据它们的返回结果或异常决定下一步。

### 7.4 发送文字问答并返回结果

<details>
<summary>术语解释：提示词与token</summary>

**提示词**（prompt）是交给模型的任务说明或输入文本，本例包括系统要求和用户提问。**token**是模型划分和处理文本的基本单位，可能是一个字、一个词的一部分或标点，不能直接当作固定数量的汉字或单词。

`max_tokens` 在此用于向服务端提出生成长度上限，具体支持方式由目标服务和模型决定。它不保证模型一定生成这么多内容，也不等于输出字符数。

</details>

以下是第四段模块代码。

```python
def call_silicon(user_prompt, system_prompt=None,
                 model_name=DEFAULT_CHAT_MODEL, client=None,
                 return_client=False, *, max_tokens=1024):
    if model_name not in ALLOWED_MODELS:
        raise ValueError("Model is outside the allowed list")
    text_models = MODEL_GROUPS["chat"] + MODEL_GROUPS["vision"]
    if model_name not in text_models:
        raise ValueError("Model does not belong to a text task")
    prompt = _check_text(user_prompt, "user_prompt")
    if type(max_tokens) is not int or max_tokens <= 0:
        raise ValueError("max_tokens must be a positive integer")
    messages = []
    if system_prompt is not None:
        system_text = _check_text(system_prompt, "system_prompt")
        messages.append({"role": "system", "content": system_text})
    messages.append({"role": "user", "content": prompt})
    owns_client = client is None
    client = _get_client(client)
    keep_client = False
    try:
        response = client.chat.completions.create(
            model=model_name,
            messages=messages,
            max_tokens=max_tokens,
        )
        if not response.choices:
            raise RuntimeError("The response has no choices")
        answer = response.choices[0].message.content
        if not isinstance(answer, str):
            raise RuntimeError("The response has no text content")
        keep_client = return_client
        return (answer, client) if return_client else answer
    finally:
        if owns_client and not keep_client:
            client.close()
```

可以沿一次提问的数据流追踪这个函数。

1. 检查传入的模型标识符是否在本地允许列表中，以及它是否属于文字相关任务组。
2. 检查用户输入和生成长度参数。
3. 把系统要求与用户提问组织为 `messages` 列表。
4. 创建或复用客户端，发送问答请求。
5. 从响应中取出第一项回答正文，并检查结果类型。
6. 按调用者指定的模式返回结果。

`user_prompt` 保存本次提问，`system_prompt` 可用于指定整体任务要求。函数把它们组织为消息列表，每项用 `role` 标记角色，用 `content` 保存文本。图片理解需要另外设计包含图片的消息结构。

`model_name` 接收本次请求使用的模型标识符，省略对应实参时采用默认模型标识符。`max_tokens` 是带默认值的仅限关键字形参。省略时使用默认值1024，显式提供时只能通过关键字实参指定，例如 `max_tokens=256`。它把生成长度要求传给服务端。

返回结构由 `return_client` 决定。取默认值 `False` 时，结果是回答字符串。**设为 `True` 时，结果为 `(answer, client)` 二元素元组，可以通过两个变量解包接收。**

客户端的管理规则也与此对应。函数自行创建客户端后，返回纯文本或请求出错时会关闭它。**成功把客户端一并返回时，由调用者在使用完毕后关闭。**调用者传入已有客户端时，也继续负责管理它。

### 7.5 调用模块并复用客户端

把 `Call_AI.py` 与下面的调用程序放在同一文件夹。将调用代码保存为 `main.py`，完成环境变量配置后，从该文件夹运行 `python main.py`。

```python
from Call_AI import set_api_key, get_models, call_silicon


def main():
    set_api_key()
    models = get_models(task="chat")
    if not models:
        raise ValueError("No matching chat model")
    model = models[0]
    answer, client = call_silicon(
        "Explain a Python function in three short sentences.",
        model_name=model,
        return_client=True,
        max_tokens=256,
    )
    try:
        print(answer)
        second = call_silicon(
            "Give one small example.",
            model_name=model,
            client=client,
            max_tokens=128,
        )
        print(second)
    finally:
        client.close()


if __name__ == "__main__":
    main()
```

第一次问答返回回答和客户端，第二次调用通过 `client=client` 复用连接。`finally` 在这一组操作完成或出错后关闭客户端，释放连接资源。

复用客户端只表示复用连接。本例第二次请求发送的消息中只有本次提问。**若希望模型结合前一次问答继续回答，需要扩展接口，把历史消息一并传入。**

主函数安排配置、查询和问答的先后顺序，模块函数完成各自的具体操作。客户端通过参数传递，使连接的使用与管理关系直接体现在调用代码中。

比较模型时，可以保持问题和输出要求一致，分别提供不同的模型标识符，再检查回答是否具体、是否符合事实和要求。程序得到回答后，还需要把文本作为任务结果进行核对。

```python
import os
import math
import time
import tushare as ts
import pandas as pd
import matplotlib.pyplot as plt


def get_index_components(index_code):
    token = os.environ.get("TUSHARE_TOKEN")
    if not token:
        raise ValueError("TUSHARE_TOKEN is required")
    ts.set_token(token)
    pro = ts.pro_api()
    data = pro.index_weight(index_code=index_code)
    if data is None or data.empty:
        return pd.DataFrame(columns=["con_code", "weight", "trade_date"])
    latest_date = data["trade_date"].max()
    latest = data.loc[data["trade_date"] == latest_date]
    return latest.drop_duplicates("con_code").reset_index(drop=True)


def random_sample_stocks(df_component, sample_m, seed):
    if type(sample_m) is not int or sample_m < 0:
        raise ValueError("sample_m must be a nonnegative integer")
    unique = df_component.drop_duplicates("con_code")
    if sample_m > len(unique):
        raise ValueError("Sample size exceeds the number of stocks")
    return unique.sample(n=sample_m, random_state=seed).reset_index(drop=True)
```

`get_index_components` 先读取授权配置并查询成分股权重记录，再选取返回数据中的最大日期，最后按 `con_code` 去重。后面的抽样因而使用同一个返回时点的不同股票。

最大日期对应本次查询结果中最新的记录日期。分析某个历史时点时，需要给查询函数增加日期参数，并明确采用哪个交易日的成分股信息。

`random_sample_stocks` 先检查数量，再进行无放回抽样，选中的股票在本次结果中各出现一次。返回值仍为数据表，保留原有列。抽样数量为0时返回空数据表，超过可用股票数时抛出异常。**固定种子可在输入内容、顺序和实现环境相同的条件下复现结果。**

### 8.3 下载价格并计算简单收益率

以下是第二段模块代码。

```python
def get_stock_adj_close(ts_code, start, end):
    token = os.environ.get("TUSHARE_TOKEN")
    if not token:
        raise ValueError("TUSHARE_TOKEN is required")
    ts.set_token(token)
    try:
        data = ts.pro_bar(
            ts_code=ts_code, adj="qfq", start_date=start, end_date=end
        )
    except Exception as error:
        print("Download failed", ts_code, type(error).__name__)
        return pd.DataFrame(columns=["trade_date", "close"])
    if data is None or data.empty:
        return pd.DataFrame(columns=["trade_date", "close"])
    return data[["trade_date", "close"]].copy()


def calc_daily_return(df_price):
    data = df_price[["trade_date", "close"]].copy()
    data["trade_date"] = pd.to_datetime(data["trade_date"])
    if data["trade_date"].isna().any():
        raise ValueError("Trade dates must be valid and complete")
    data["close"] = pd.to_numeric(data["close"], errors="raise")
    data = data.sort_values("trade_date").drop_duplicates("trade_date")
    data = data.reset_index(drop=True)
    if (
        data["close"].isna().any()
        or not data["close"].map(math.isfinite).all()
        or (data["close"] <= 0).any()
    ):
        raise ValueError("Prices must be finite, positive and complete")
    data["ret"] = data["close"].pct_change(fill_method=None)
    if not data["ret"].iloc[1:].map(math.isfinite).all():
        raise ValueError("Returns exceed the finite numeric range")
    return data
```

下载函数使用 `adj="qfq"` 取得前复权价格。复权用于调整分红送转等公司行为对价格序列的影响，分析和图形中的价格口径应保持一致。

行情请求在 `try` 中出错时，函数输出股票代码和异常类型，再返回空数据表。服务返回 `None` 或空数据表时，也返回具有指定列名的空数据表。批量函数因此可以统一使用 `.empty` 判断是否有价格记录，再决定是否处理下一只股票。授权配置缺失等在请求前检查出的错误，则会直接传给调用者。

收益率函数使用简单收益率公式 `r_t = P_t / P_(t-1) - 1`，其中 `P_t` 为当前记录的收盘价，`P_(t-1)` 为前一条记录的收盘价。例如，价格从100变为105，收益率为 `105 / 100 - 1 = 0.05`，按百分数显示为5%。

**代码先把日期转换为日期类型，再按升序排列并删除重复日期，最后计算收益率。**`pct_change()` 比较当前行和前一行，按时间排序后，这两个位置才具有公式要求的先后关系。第一行缺少本表内的上一期价格，因此收益率为缺失值 `NaN`。

`pct_change()` 返回的是相对变化率，0.05表示5%，不会自动乘100。这里pandas用 `NaN` 表示缺失的浮点结果，不等于零收益率。

`fill_method=None` 使计算保留缺失值的含义。函数要求日期有效且非缺失，价格也须非缺失、有限且大于0，检查失败时抛出异常。**收益率采用浮点数计算，除第一项允许为缺失值外，后续结果若超出有限浮点数的表示范围，也会抛出异常。**对日行情来说，相邻记录通常是相邻交易日，中间可能跨越周末或节假日。

### 8.4 批量调度与请求间隔

以下是第三段模块代码。

```python
def batch_download_and_calc_return(code_list, start, end, sleep_sec):
    if not math.isfinite(sleep_sec) or sleep_sec < 0:
        raise ValueError("sleep_sec must be finite and nonnegative")
    results = {}
    for code in dict.fromkeys(code_list):
        try:
            prices = get_stock_adj_close(code, start, end)
            if prices.empty:
                continue
            results[code] = calc_daily_return(prices)
        finally:
            time.sleep(sleep_sec)
    return results
```

`dict.fromkeys(code_list)` 按首次出现的顺序保留不同代码，避免重复请求同一只股票。每轮循环下载一只股票的价格，空数据表直接跳过，有效价格交给收益率函数处理，再以股票代码为键存入结果字典。

本轮处理正常完成、执行 `continue` 或抛出异常后，都会进入 `finally`，按 `sleep_sec` 指定的秒数等待。该参数可以为小数，且必须是有限非负数。函数会在开始请求前检查这一条件，具体间隔需要根据实际服务的请求频率规则设置。

价格表的结构或内容不符合约定时，收益率函数抛出的异常继续传给调用者，批量过程随之结束。需要让批量任务在这类错误后继续执行时，可以再设计逐只股票的错误记录与处理规则。

```python
def plot_price_return_subplot(data_dict):
    if not data_dict:
        print("No valid stock data")
        return
    fig, axes = plt.subplots(
        nrows=len(data_dict), ncols=2,
        figsize=(12, 3 * len(data_dict)), squeeze=False,
    )
    for row, (code, data) in enumerate(data_dict.items()):
        price_axis, return_axis = axes[row]
        price_axis.plot(data["trade_date"], data["close"])
        price_axis.set_title(code + " adjusted close")
        price_axis.set_ylabel("Price")
        return_axis.plot(data["trade_date"], data["ret"])
        return_axis.axhline(0, color="gray", linewidth=0.8)
        return_axis.set_title(code + " daily return")
        return_axis.set_ylabel("Return")
        for axis in (price_axis, return_axis):
            axis.grid(alpha=0.3)
            axis.tick_params(axis="x", rotation=30)
    fig.tight_layout()
    plt.show()
```

结果字典为空时，函数先输出提示并返回。存在数据时，`squeeze=False` 使 `axes` 保持二维数组结构，只有一只股票时也能按同样的行、列关系访问子图。

每只股票对应一行，左图显示价格，右图显示收益率。收益率图中的水平零线便于观察正负变化，横轴标签旋转后也更容易区分日期。示例采用英文标签，便于在基础字体环境中显示。

## 9. 复习提要

- 递归需要正确基例、同类子问题和能够到达基例的缩小过程。
- 调用展开时保存每层状态，基例返回后逐层完成剩余计算。
- 计算代价需要同时观察递归深度、分支数和重复子问题。
- 代码复用依赖明确接口。模块化设计强调高内聚、低耦合和分层抽象。
- 模块间通过参数与返回值传递数据，主函数负责组织整体流程。
- API 案例中要看清配置、客户端、模型选择、请求、结果接收分别由谁负责。
- 数据处理案例中要看清输入类型、排序、空结果和返回结构的约定。

**第1题 C**

**第4题 B**

形参 `n` 的值从1开始递增，持续远离0。实际执行通常在触及递归深度限制时引发异常。

**第5题 C**

进入形参 `n` 的值为2和1的两层时，先分别输出2、1。形参 `n` 的值为0的基例返回后，两层按相反顺序继续执行，再输出1、2，所以结果为 `2112`。

**第6题 B**

先反转剩余的 `"B"` 得到 `"B"`，再把首字符 `"A"` 接到末尾，结果为 `"BA"`。

**第7题 A**

`s[1:]` 去掉当前首字符，长度每次减1，直到空字符串。这个尺度说明递归能到达基例。

**第8题 D**

前六项依次为1、1、2、3、5、8，因此 `F(6) = 8`。

**第9题 C**

例如计算 `F(5)` 时，`F(3)` 在不同分支中重复出现。输入增大后重复子问题快速增加。

**第10题 A**

基例给出1，递归每层加上当前 `n`，整体结果为 `1 + 2 + ... + n`。

**第11题 D**

从3到0共有三个非基例层，每层贡献2，结果为 `2 + 2 + 2 + 0 = 6`。

**第12题 B**

`f(1)` 调用 `f(0)` 并得到7，随后直接运行到函数末尾。由于这一层没有执行显式的 `return`，最终返回 `None`。

**第13题 C**

各次调用分别保存自己的局部绑定和待完成操作。内层返回后，外层继续使用保留的状态。

**第14题 A**

明确形参与返回值约定后，计算模块可以接收来自不同来源的价格序列，也便于用小规模人工数据验证。

**第15题 D**

高内聚使模块内部功能围绕共同职责组织，低耦合使模块之间的依赖通过明确接口表达。

**第16题 B**

主函数负责流程编排，计算和展示的具体步骤由对应函数实现。外部服务是否可用需要实际调用及错误处理判断。

**第17题 C**

实现先取得服务端列表，再与本地允许列表匹配，并按调用时指定的任务组筛选，最终结果取决于这几个条件。

**第18题 A**

返回值为二元素元组，A项用两个变量分别接收回答与客户端。B项有三个变量，解包数量不匹配。C、D两项分别尝试把元组与整数相加、把元组转成整数，都会引发类型错误。
